# GrowUp Product Decisions v1

## 결정 1 — 카드 수 목표를 없앤다

120장이나 150장 같은 수량 목표는 사용자가 실제로 수행하는 행동보다 콘텐츠 양을 우선하게 만든다. GrowUp v1은 **아이가 일상에서 관찰할 수 있는 필수·독립 행동**만 카드로 만든다.

카드로 만들지 않는 경우:

- 이미 다른 카드의 단계 또는 반복인 행동 (예: 발 씻기 → `몸 씻기`의 단계)
- 결과를 평가하는 표현 (예: 골고루 먹기, 깨끗하게 정리하기)
- 부모가 대신 판단해야 하는 추상 표현 (예: 착한 아이 되기)
- 화면에서 독립적으로 관찰하거나 선택할 수 없는 행동

## 결정 2 — 카테고리는 6개, 자립은 관찰 결과다

`자립`은 행동 영역이 아니라 모든 행동에서 관찰되는 결과다. 별도 카드 영역으로 두면 손 씻기·옷 입기 같은 기존 행동과 중복된다. 따라서 v1의 카드 영역은 다음 6개로 정한다.

1. 개인 위생
2. 옷 입기
3. 식사
4. 물건과 집안일
5. 외출 준비
6. 안전과 도움 요청

각 카드에서 아이가 `혼자`, `같이`, `안 해봤어요`를 선택한다. 이 상태의 축적이 곧 자립의 변화다.

## 결정 3 — 행동은 선형 목록이 아니라 느슨한 트리다

아동의 행동은 모두 같은 순서로 발달하지 않는다. 따라서 카드 잠금이나 강제 순서는 사용하지 않는다.

- `선행 기술`: 다음 행동을 더 쉽게 만드는 기술
- `권장 다음 행동`: 관찰 후 자연스럽게 제시할 한두 가지 행동
- `대체 경로`: 같은 목표로 가는 다른 행동

예를 들어 손 씻기와 양치하기는 둘 다 위생의 시작점이지, 손 씻기를 완료해야만 양치를 할 수 있는 관계가 아니다. 발 씻기는 독립 카드가 아니라 `몸 씻기`의 부모 가이드에 포함한다.

## 결정 4 — Flutter를 채택한다

Flutter는 Android와 iOS를 하나의 코드베이스로 만들 수 있고, 큰 그림·큰 터치 영역 중심의 일관된 화면을 구현하기 좋다. GrowUp은 콘텐츠 중심의 모바일 앱이며 네이티브 전용 기능이 초기 핵심이 아니므로 Flutter가 적합하다.

단, v1은 Flutter의 복잡한 상태 관리나 서버를 먼저 도입하지 않는다. 로컬 JSON 카드와 기기 내 관찰 기록으로 시작하고, 실제 가족 사용 검증 후 동기화·계정 기능을 결정한다.

## v1 완료 기준

- `ACTION_TREE_V1.md`의 26개 행동이 중복 없이 카드로 정의됨
- 모든 카드에 아이용 제목, 부모 가이드, 선행 기술, 권장 다음 행동이 있음
- 카드 원본과 관찰 기록의 데이터 모델이 분리됨
- Flutter에서 카드 선택과 상태 기록을 오프라인으로 사용할 수 있음
