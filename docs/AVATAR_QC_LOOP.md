# 아바타 공간 QC 루프

아바타 공간은 한 번 보고 끝내지 않고 아래 순서를 반복해 품질을 올립니다.

1. **구조 검사**: 캐릭터가 바닥 안에서 시작하는지, 가구를 뚫지 않는지, 모든 물건 앞에 상호작용 자리가 있는지 확인합니다.
2. **화면 Critic**: 360×640 실제 휴대폰 화면을 방마다 캡처해 글자 잘림, 가구 겹침, 캐릭터 크기, 버튼 가림을 확인합니다.
3. **성장 연결 검사**: 행동 카드 → 보상 물건 → 맞는 방의 배치 슬롯 → 캐릭터 행동이 끊기지 않는지 확인합니다.
4. **통합 성능 검사**: 방을 연속으로 넘기고 캐릭터를 움직인 뒤 Android 프레임 통계를 기록합니다.
5. **회귀 검사**: 홈, 행동 고르기, 아이 모드, 부모 모드, 성장 기록 테스트를 다시 실행합니다.
6. **다음 라운드**: 실패나 경고를 수정한 뒤 같은 검사를 최소 두 번 반복합니다.

## 합격 기준

- 여섯 공간 모두 구조 점수 75점 이상
- 치명적(`fail`) 구조 문제 0개
- `flutter analyze` 오류 0개
- 전체 Flutter 테스트 통과
- Android APK 빌드 성공
- 에뮬레이터가 연결된 경우 설치·실행·방 전환 성공
- Profile 빌드의 큰 끊김(33.3ms 초과) 5% 이하, P90 합산 프레임 24ms 이하
- 화면 캡처에서 캐릭터 발과 그림자가 바닥에 붙어 있음
- 기본 물건의 보이는 아래쪽과 논리 바닥점이 일치함
- 기본 물건의 그림 전체와 최소 가로 18·세로 14 범위를 누를 수 있음
- 이동 시간은 실제 이동 거리 ÷ 초당 바닥 좌표 10으로 계산됨
- 상호작용 중 캐릭터가 선택한 기본 물건에 완전히 가려지지 않음
- 공간 상단 상태 안내와 하단 조작부가 배경의 핵심 가구를 과도하게 가리지 않음

## 실행 방법

```powershell
powershell -ExecutionPolicy Bypass -File tool\run_avatar_qc.ps1 `
  -Flutter C:\path\to\flutter.bat `
  -Adb C:\path\to\adb.exe `
  -Rounds 2
```

결과는 `build/avatar_qc/<실행시각>/`에 저장됩니다.

- `report.txt`: 각 라운드의 분석·테스트 결과
- `room-*.png`: 에뮬레이터의 방별 화면
- `gfxinfo.txt`: Android 프레임 성능 원본 기록

## 앱 안에서 확인

`--profile --dart-define=AVATAR_QC=true` 빌드에서는 상단의 방패 체크 아이콘을 눌러 현재 공간의 다음 항목을 볼 수 있습니다. 실제 성능 판정에는 디버그 빌드가 아니라 Profile 빌드를 사용합니다.

- 공간 좌표
- 상호작용
- 성장 연결
- 접근성
- 구성 성능
- 실제 Build/Raster 프레임과 끊김 비율

이 패널은 아이가 쓰는 일반 release 화면에는 표시하지 않습니다.
